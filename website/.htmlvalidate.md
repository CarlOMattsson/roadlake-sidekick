# html-validate exceptions

`.htmlvalidate.json` cannot hold comments, so the reason for each switched-off rule is here. Everything else in
`html-validate:recommended` runs over `dist/**/*.html`. The rules below are switched off because Astro, Starlight or Expressive Code
produce the markup, not because the site's own markup was checked and found acceptable.

| Rule | Why it is off |
| --- | --- |
| `void-style` | Astro writes `<meta/>` and `<link/>`. Both forms are valid HTML5. |
| `no-inline-style` | Starlight (selects, search button) and Expressive Code write `style` attributes. The CSP allows them with `style-src-attr` only (see `integrations/csp-inline-hashes.mjs`). |
| `no-implicit-button-type` | Starlight's search, menu and copy buttons have no `type`. None of them is inside a form. |
| `valid-id` | `#_top` is Starlight's skip-link target. |
| `element-permitted-content` | Expressive Code puts `<div>` inside `<code>` and `<button>`. |
| `text-content` | Expressive Code's copy button has its name in `title`/`aria-label`, checked by axe in `tests/site.spec.ts`. |
| `unique-landmark` | Starlight writes both the mobile and the desktop table of contents as `<nav>` with the same name, and shows one at a time. html-validate cannot see that. `tests/site.spec.ts` runs axe's `landmark-unique` on the rendered page instead, which only counts visible landmarks. |
| `long-title` | Page titles come from the document headings plus the site name. |
| `prefer-native-element` for `region` | The scrolling strips are `role="region"` with an `aria-label` and `tabindex`, so keyboard users can scroll them. |

Starlight's own elements (`starlight-*`, `site-search`, `mobile-starlight-toc`) are accepted by the default custom-element rule.
